# instalink_bot

Telegram-бот, который отправляет Instagram Reels и видеопосты как видео в чат.
Работает на **Telegram Serverless**: отдельный VPS, Cloudflare Worker и постоянно
запущенный процесс для бота не нужны.

## Что умеет

- Распознаёт ссылки на Reels и видеопосты в сообщениях, подписях и скрытых ссылках.
- Отправляет видеофайл, который можно смотреть и пересылать в Telegram.
- Сохраняет Telegram `file_id` в SQLite. Повторная ссылка использует уже загруженное видео.
- Работает в личных сообщениях и группах, сохраняет тему при ответе в форуме.
- Повторяет запрос при сетевом сбое или HTTP 5xx и пробует следующий сервис,
  если предыдущий не смог отдать видео.
- При ошибке предлагает открыть оригинал или ссылку с предпросмотром.

## Быстрый запуск

### 1. Создайте бота

В [@BotFather](https://t.me/BotFather):

1. Создайте бота через `/newbot` или выберите существующего.
2. Включите для него **Serverless**. Доступность функции зависит от вашего аккаунта.
3. Откройте **CLI Access** и получите токен для CLI.

Токен CLI отличается от обычного Bot API token. Вставляйте его в локальный запрос
`tgcloud login`; в исходниках и GitHub он не нужен.

Если этот бот уже работал через Python или Cloudflare Workers, остановите прежний
обработчик перед переключением. Один бот не может одновременно получать обновления
через несколько webhook или через webhook и long polling.

### 2. Установите проект

Понадобятся Git и Node.js **22.13 или новее**; для разработки подойдёт Node.js 24.
Команды одинаковы для PowerShell, Bash и терминала macOS:

```sh
git clone https://github.com/weird-aftertaste/instalink_bot.git
cd instalink_bot
npm ci
```

### 3. Проверьте код и выполните деплой

```sh
npm test
npm run check
npx tgcloud login
npm run deploy
npx tgcloud migrate --dry-run
npx tgcloud migrate --safe
```

`login` запросит токен CLI. Деплой загрузит JavaScript-модули и настроит webhook.
Миграция создаст таблицу `media_cache` для сохранённых Telegram file ID.
**Деплой кода сам по себе не создаёт таблицы.**

Настройки подключения и токен CLI хранятся локально в `.tgcloud/`.
Эта папка исключена из Git. После клонирования на другую машину выполните `login` снова.

### 4. Отправьте ссылку

Напишите боту `/start`, затем отправьте ссылку на публичный Reel или видеопост:

```text
https://www.instagram.com/reel/SHORTCODE/
```

Поддерживаются пути `/p/`, `/reel/`, `/reels/` и `/tv/`.
Бот обрабатывает до трёх уникальных ссылок в одном сообщении.
В повторном сообщении с той же ссылкой видео должно отправляться из кэша.

### 5. Добавьте бота в группу

Добавьте бота в нужную группу. Чтобы он получал обычные сообщения со ссылками,
отключите privacy mode через `/setprivacy` в @BotFather. У бота должно быть право
отправлять сообщения и видео. Для групп с темами ответ уходит в исходную тему.

## Откуда берётся видео без Instagram-аккаунта

Серверлес-бот не входит в Instagram и не хранит Instagram cookies. Он запрашивает
метаданные через `vxinstagram.com`, затем при необходимости через `kkinstagram.com`.
Эти сервисы возвращают адрес видео. Как они получают доступ к Instagram, зависит
от их реализации: у них могут быть собственные аккаунты или сессии.

Сначала бот передаёт адрес видео в Telegram. Если Telegram не может скачать файл,
бот скачивает его через SDK и отправляет как MP4-вложение. После успешной отправки
бот сохраняет `file_id`, поэтому повторные запросы обходятся без извлечения видео.

Публичные сервисы могут перестать работать, ограничить запросы или вернуть
устаревшую ссылку. Размещение бота в Telegram не отменяет ограничений Instagram.

## Настройки

Публичные настройки находятся в [tgcloud/lib/config.js](tgcloud/lib/config.js).

| Параметр | По умолчанию | Что меняет |
| --- | --- | --- |
| `cobaltApiUrl` | пустая строка | Адрес своего или разрешённого вам Cobalt API |
| `embedOrigins` | vxinstagram, kkinstagram | Порядок сервисов для извлечения видео |
| `fetchAttempts` | `2` | Число попыток при сетевых ошибках и HTTP 5xx, максимум 3 |
| `maxLinksPerMessage` | `3` | Максимум уникальных ссылок в сообщении |
| `maxUploadBytes` | `49000000` | Предел скачивания перед загрузкой в Telegram |
| `maxMetadataChars` | `1000000` | Максимальный размер HTML с метаданными |

При HTTP 429 бот переходит к другому сервису без немедленного повторного запроса.
После изменения настроек выполните `npm run deploy` из каталога проекта.

### Необязательный Cobalt API

Для контроля над извлечением можно указать HTTPS-адрес собственного Cobalt v10+
или инстанса, владелец которого разрешил вам доступ. Он будет проверяться первым.
Cobalt запускается отдельно, на хостинге с поддержкой его зависимостей.

Публичный `api.cobalt.tools` не предназначен для подключения сторонних ботов без
разрешения владельцев. Текущий адаптер не поддерживает API-ключи и CAPTCHA.
Не записывайте токены в `config.js`.

## Если видео не отправляется

| Что произошло | Что проверить |
| --- | --- |
| Сервисы не вернули видео | Публикация доступна всем, а сервисы из `embedOrigins` работают. Повторите запрос позже. |
| Видео найдено, но не скачалось | CDN или сервис мог временно заблокировать запрос. Повторите попытку. |
| Превышен предел загрузки | По умолчанию бот скачивает файлы размером до 49 МБ. |
| Не поддерживается формат файла | Сервис вернул HTML, фото или другой файл вместо MP4. |
| Telegram отклонил видео | Формат или содержимое файла не подходит для отправки как видео. Транскодирования в проекте нет. |
| Бот отвечает в личке, но молчит в группе | Проверьте `/setprivacy` и право отправлять видео. |
| Повторная ссылка скачивается заново | Выполните миграцию и проверьте наличие таблицы `media_cache`. |
| Обновления перестали приходить | Проверьте webhook и убедитесь, что старый бот не запускает polling или свой webhook. |

Проверка подключения и webhook:

```sh
npm run status
npx tgcloud webhook
```

В логах записываются хост сервиса, этап ошибки и HTTP-статус, когда он известен.
Подписанные адреса видео и полные ответы сервисов в логи не выводятся.
`npx tgcloud run` выполняет код **на реальном боте** и может отправлять сообщения.

## Ограничения

- Поддерживаются публичные видеопубликации. Закрытые посты, Stories, фото и короткие
  ссылки `/share/` не обрабатываются.
- Для карусели отправляется первое видео, которое вернул сервис; загрузки всего альбома нет.
- По документации Bot API отправка файла по URL ограничена 20 МБ, multipart-загрузка
  видео ограничена 50 МБ. В проекте установлен предел 49 МБ для скачивания.
- SDK собирает файл в памяти. Лимиты памяти и времени Telegram Serverless могут
  ограничивать размер сильнее; при необходимости уменьшите `maxUploadBytes`.
- Повторная доставка одного обновления Telegram может привести к повторной отправке
  видео. Постоянной дедупликации обновлений нет.
- Тесты проверяют обработку ошибок, кэш и подготовку загрузки с подставными HTTP/API.
  Они не гарантируют доступность внешних сервисов и доставку конкретного видео.

## Обновление

Из каталога проекта:

```sh
git pull --ff-only
npm ci
npm test
npm run check
npm run deploy
```

Если менялся `tgcloud/schema.js`, после деплоя выполните:

```sh
npx tgcloud migrate --dry-run
npx tgcloud migrate --safe
```

`--dry-run` показывает план миграции, а `--safe` применяет изменения,
которые CLI считает безопасными. Просмотрите план перед применением.
